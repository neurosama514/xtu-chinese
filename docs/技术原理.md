# 技术原理

XTU 7.14.2.135 是 WPF / .NET Framework 4.x 程序，界面文案分散在四类载体里。
本工具对每一类分别处理，最后用 Mono.Cecil 把改动写回程序集。

## 1. BAML（编译后的 XAML）

`Client\PerfTune.exe` 的嵌入资源 `PerfTune.g.resources` 里有 105 个 `.baml`。
BAML 是 XAML 的二进制形式，文本以 UTF-8 存在记录里，长度前缀可变。

WPF 官方提供的 `BamlLocalizer` 只能处理**带 `x:Uid`** 的 BAML（Intel 编译时关闭了 Uid 生成），
所以本项目改用内部的 `MS.Internal.Globalization` 语法树 API：

```
BamlResourceDeserializer.LoadBaml(stream)  →  BamlTree
    ↓ 遍历节点（BamlPropertyNode / BamlTextNode / BamlLiteralContentNode）
    ↓ 替换 Value / Content
BamlResourceSerializer.Serialize(localizer, tree, outStream)  →  新 BAML
```

实现见 `src/tools/XtuBaml.cs`，三个模式：

- `dump`：导出所有可翻译节点（`file / index / kind / owner / prop / value`）
- `apply`：按 `file|index → 新文本` 的映射表就地替换并重新序列化
- `validate`：用真正的 `System.Windows.Baml2006.Baml2006Reader` 逐个解析，确认语法树合法

注意点：`BamlTextNode.Content` 是只读属性，替换时必须新建节点并挂回父节点。

## 2. 内嵌主题 XAML

`PerfTune.Initialization.IntelBlueColorTheme.xaml` / `IntelDarkColorTheme.xaml`
是**纯文本 XAML**，页面上大段说明文字以 `Value= "..."`（注意等号后可能有空格）存在：

```xml
<Style x:Key="SpeedOptimizerDescription" TargetType="{x:Type TextBlock}">
  <Setter Property="Text" Value= "When enabled this feature automatically overclocks ..." />
</Style>
```

由于该文件被 XTU 以 `Encoding.Default` 之外的路径读取时可能踩到编码问题，
替换时把中文写成 **XML 数字字符引用**（`&#x6838;`），保证文件仍是纯 ASCII，
任何解码方式都不会乱码。实现见 `src/scripts/patch_themes.py`。

## 3. 服务端元数据 XML

`Client\IntelOverclockingSDK.dll` 内嵌两个元数据文件：

- `IntelOverclockingSDK.Metadata.KnobMetadata.xml`（约 93 KB）：每个调参项的
  `Name` / `Description` / `Enumeration`
- `IntelOverclockingSDK.Metadata.MonitorMetadata.xml`（约 48 KB）：监控项同上

这两个文件是纯 XML，按 `kind + 原文` 建索引后整段替换即可
（`src/scripts/build_maps.py` 中的 `patch_xml`）。

## 4. 程序字符串常量

界面里大量文案是代码里的 `ldstr` 字面量（导航项、消息框、拼接片段）。
用 Mono.Cecil 遍历所有方法体，把 `OpCodes.Ldstr` 的操作数按映射表替换，
写回时 Cecil 会重建 `#US` 字符串堆（`src/tools/XtuPatch.cs` 的 `patchasm` 模式）。

同时该模式支持两种附加操作：

- `resmap`：替换嵌入资源（用于换掉 `.g.resources`、`Category.xml`、主题 XAML、元数据 XML）
- `neutmap`：把指定方法改写为 `return <常量>`（用于跳过签名自校验，见下）

### 重建 .g.resources 的坑

`ResourceReader.GetResourceData` 对 `ResourceTypeCode.Stream` 条目返回的数据
**包含 4 字节长度前缀**，而 `ResourceWriter.AddResource(name, Stream)` 又会再写一个前缀。
所以重建时必须先剥掉原前缀、再交给 `AddResource(Stream)`，否则 BAML 前面会多出 4 字节，
运行时表现为 `EndOfStreamException`（`Baml2006Reader.Process_Header`）。

## 5. 签名自校验

XTU 启动时调用：

```csharp
// Intel.Overclocking.SDK.SoftwareTrustVerification.SoftwareTrustVerification
// 由 PerfTune.AppManager.AdminCheck() 调用
CreateLogFile()  → 逐文件 WinVerifyTrust + 固定证书链校验
```

被校验的文件列表（`dllList`）包含本工具要改的全部 DLL，所以必须绕过。
做法是把 `CreateLogFile()`（两个重载）改写为 `ldc.i4.1; ret`，
即直接返回"校验通过"。除该校验外不改动任何逻辑。

## 6. 打包

`src/installer/Setup.cs` 是一个 WinForms 安装器：

- 把汉化后的 5 个文件和**原始英文文件**（用于还原）以 Deflate 压缩后作为嵌入资源
- 以 `requireAdministrator` 清单启动
- 安装：结束 PerfTune → 备份原文件到 `%ProgramData%\XTU-CN\backup` → 覆盖 → 重启
- 还原：从备份拷回
- 可选：内置官方 `XTUSetup_7.14.2.135.exe`，未检测到 XTU 时先引导安装
- 支持 `/install`、`/restore` 静默参数，日志写入 `%ProgramData%\XTU-CN\setup.log`
