# 已知问题

## 仍未汉化的部分

| 位置 | 说明 | 原因 |
|---|---|---|
| 系统信息表格字段名 | Brand String、Family、Model、Feature Flags、Instructions… | 由后台服务 `Drivers\HardwareAccess.dll` 运行时提供，属服务侧 DLL，改动风险高（会影响 XtuService） |
| 基准测试页顶部概述 | "Intel XTU Benchmark 2.0 is an improved benchmark…" | 在安装目录全部文件中未找到明文来源，疑似服务/驱动运行时下发 |
| 配置文件列表列名 | `Benchmark`、`Score` | 由配置文件模型/服务端提供 |
| 配置名 | `Default`、`Active` | 属数据而非界面文案，翻译会影响按名查找 |
| 帮助文档 | `XTU_help.chm` | 英文 CHM，未翻译 |
| 部分监控项 | `CPU Utilization`、`Memory Utilization` | 来自 `Xtu3ServiceLayer.dll` 的性能计数器名称，与系统计数器键耦合 |
| 顶栏按钮 | `Settings`、`Help` | 文案来源未定位（疑为图标按钮的 AutomationName） |

## 版本限制

只适配 **7.14.2.135**。XTU 每次更新都可能改变：

- BAML 结构与控件数量（`baml_map.tsv` 的 index 会失效）
- 被校验的文件列表（`dllList`）
- 字符串常量内容

换版本后需要重新执行 `extract → generate → patch`，并对新增文案补翻译。

## 风险与副作用

1. **数字签名失效**：修改后的文件不再是 Intel 签名，Windows 可能提示"未知发布者"，
   SmartScreen 也可能拦截安装包；不影响功能。
2. **签名校验绕过**：`CreateLogFile()` 被改写为恒返回 `true`。如果 Intel 后续把这个校验
   移到别处（服务侧、驱动），补丁会失效，表现为启动弹窗 "XTU signature validation failed"。
3. **更新覆盖**：Intel 官方更新/修复安装会覆盖汉化文件，需要重新打补丁。
4. **服务侧未改动**：驱动与 `XtuService` 相关 DLL 一律未修改，保证调参/监控功能正常。

## 排错

- 启动弹窗签名校验失败 → `apply\neut_sdk.tsv` 未生效，检查 `IntelOverclockingSDK.dll` 是否被替换
- 界面报错/白屏 → BAML 不兼容，执行 `build.ps1 -Stage restore` 还原
- 想彻底恢复 → 运行安装包的"还原为英文原版"，或 `build.ps1 -Stage restore`
